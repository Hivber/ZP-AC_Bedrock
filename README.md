# ZP-AC Bedrock

ZP-AC 是一套面向 Minecraft Bedrock 1.26.60 的反作弊系统，采用**一个行为包 + 一个资源包（合并为单一 mcaddon）+ 一个 Endstone 增强插件**的交付结构。

- 行为包：2.1.9。无插件时独立运行，负责基础行为采样、本地历史记录、举报 UI、管理员面板和可配置检测开关。
- 资源包：1.0.0。提供 ZP-AC 品牌标志、反作弊盾牌、信用分、举报和菜单图标；随行为包一起导入。
- Endstone 增强插件：0.6.9。提供服务端原生事件检测、UUID 持久化画像、风险关联、待复核候选、可选自动踢出、人工确认永久封禁和可选云端 UUID 同步。
- 云端功能默认关闭；云端仅同步 UUID，不上传玩家名称、XUID、可信分、风险分或证据正文。

## 部署

1. 将构建产物 `ZP-AC-2.1.9.mcaddon`（内含行为包与资源包） 导入 Minecraft/Bedrock 服务端，并在目标世界启用行为包。
2. 将 `endstone_zp_report_anticheat-0.6.9-py3-none-any.whl` 安装到 Endstone 0.11.15 / Python 3.11 环境。
3. 重启服务器，确认日志中出现 ZP-AC 0.6.9 启用信息和行为包握手信息。

兼容基线：Minecraft Bedrock 1.26.60.6、Protocol 2225、Endstone 0.11.15、Python 3.11、`@minecraft/server` 2.10.0、`@minecraft/server-ui` 2.2.0。

## 公开信用分系统（Endstone 0.6.9）

- 所有玩家可执行 `/zp`，只输出一行自己的公开信用分；不包含隐藏可信分、风险分、UUID、证据数或其他画像字段。普通玩家不能查询他人分数。
- 管理员可执行 `/zpac credit <在线玩家名|UUID>` 查询他人公开信用分；仅 OP 或带有 `zp_ac_admin` / `zp:ac_admin` 管理员标签的账号可执行，且该命令只返回公开信用分，不展示隐藏画像。
- 新玩家公开信用分初始为 100；公开信用分独立于隐藏可信分，旧玩家画像迁移时默认补为 100，不会把内部可信分直接暴露或复制到公开分。
- 仅高置信度强规则（speed、flight、极端 reach、多目标异常战斗）会扣公开信用分；AI 线索和弱辅助证据不会直接扣分。
- 短时间内对同一玩家至少 8 次单方面造成伤害，且对方没有在同一窗口反击，默认扣 5 分；互相还击的正常 PvP 不按骚扰处理。每个攻击者/受害者组合有 10 分钟处罚冷却。
- 公开信用分按实际在线活动时间每满 1 小时恢复 0.5 分，最高 100 分；不足 1 小时的恢复进度保存在 UUID 玩家画像中，插件/服务器重启后继续累计，不会清零。每次扣分后重新累计下一小时正常在线时间。
- 公开信用分低于 70 时，服务器端取消该玩家对其他玩家造成的伤害事件，并通过 ActionBar 显示“信用分过低”；对怪物和其他非玩家目标不受影响。70 分本身仍允许 PvP。
- 低分玩家受到某玩家攻击后，可在 5 秒内对同一攻击者正常还手；该反击不受 70 分门槛拦截，也不计入单方面攻击骚扰扣分。超过 5 秒或攻击其他玩家仍受原限制。
- 公开信用分 PvP 门槛适用于所有在线玩家，包括 OP 和管理员；反作弊检测豁免不等于公开信用分豁免。
- 分数保存在插件本地 UUID 画像文件中；公开命令不显示 UUID、隐藏可信分、风险分或检测证据。

## 管理入口

- `/ba`（行为包自定义命令命名空间为 `zp_ac:ba`）：打开 ZP 综合菜单，包含“查看我的信用分”和“举报其他玩家”两个入口。
- `/zp_ac:admin`：打开 ZP-AC 管理控制台。
- `/zpac`：Endstone 命令行管理入口。

行为包管理员 UI 通过标签授权。为非 OP 管理员添加标签：

```mcfunction
/tag <玩家名> add zp_ac_admin
```

安装 Endstone 插件后，插件会把 OP 状态镜像到保留标签 `zp_ac_op_admin`，使 OP 能直接打开管理 UI。请勿手动给普通玩家添加 `zp_ac_op_admin`；插件会按实际 OP 状态维护它。

管理员主菜单新增“反作弊检测功能开关”，管理员可单独启用/关闭移动速度、飞行/悬浮、超距攻击、多目标战斗、连点器、自动搭路和快速破坏方块检测、矿物透视异常定向采矿检测。新安装默认全部启用；选择保存在世界动态属性中，插件在线时由管理员 UI 同步保存，插件重连时行为包会重新同步。快速破坏方块检测和矿物透视异常定向采矿检测仅由 Endstone 增强层提供。矿物透视检测分析服务端记录的岩石/矿物开采比例、稀有矿物数量及空间分布；无法直接读取玩家客户端是否安装透视模组，因此只生成低权重辅助证据，不会单独触发自动踢出或永久封禁。原有插件增强管理菜单仍可查看待复核候选、查询隐藏画像、人工确认永久封禁、撤销 UUID 封禁和管理云端同步。

## 安全与处罚原则

- 举报数量本身不触发自动踢出。
- 单一检测项不直接导致永久封禁。
- 自动踢出需要多种规则、强证据和持续风险门槛共同满足。
- 永久封禁必须通过管理员明确确认。
- OP 和管理员标签账号默认豁免反作弊检测。
- 云端默认关闭；启用时要求 HTTPS（仅 localhost 开发测试允许 HTTP）。
- 玩家画像文件以 UUID 为键，只保存数值与规则统计；本地证据和候选文件可能包含玩家名称，仅保留在服务器本地数据目录。

## 通信与控制台日志

行为包与插件通过以下 ScriptEvent 通信：

- `zp:report_submitted`：举报消息。
- `zp:ac_plugin_ready`：插件心跳/就绪握手。
- `zp:ac_bp_evidence`：行为包检测证据。
- `zp:ac_admin_request` / `zp:ac_admin_response`：管理员 UI 请求与响应。
- `zp:ac_checks_sync`：行为包与 Endstone 同步管理员检测开关。

插件每 30 秒刷新一次握手，行为包使用 90 秒租约。该间隔用于明显降低控制台重复输出，同时保留插件离线检测和自动恢复能力。管理请求只允许在线 OP 或持有管理员标签的玩家，并在插件端再次验证。

## 本地构建

要求 Python 3.11+、Node.js 22+、可安装 setuptools / wheel / build。

```bash
python -m pip install --upgrade build
node --check --input-type=module < mcaddon/scripts/main.js
python -m compileall -q plugins/endstone_zp_anticheat
python tools/build_release.py
```

构建产物输出到 `dist/`，包含一个 `.mcaddon` 和一个 `.whl`。GitHub Actions 会在 main 分支更新后自动执行静态检查并上传这两个成品。

## 验收边界

CI 会执行 JavaScript 语法检查、Python 编译检查、清单/版本一致性检查，并生成两个发行包。CI 不模拟真实 Bedrock 客户端、Endstone 事件循环或多玩家服务器；最终验收仍需在实际 1.26.60.6 + Endstone 0.11.15 服务器中测试命令注册、举报、管理员 UI、封禁/撤销和云端连接。

 
## 本地 AI 行为分析（Endstone 0.6.9）

插件内置无第三方依赖的本地统计行为分析引擎（Local Robust Baseline v1）。它从服务端观测到的移动速度、战斗事件、矿物/岩石开采、点击间隔和方块放置行为中构建时间窗口特征，并基于每名玩家自己的历史基线识别多维异常组合。首次运行需要积累基线样本；基线在插件运行期间内存维护，重启后重新预热。

AI 线索只写入本地 evidence.jsonl 并通知管理员，不增加玩家风险分、不进入自动踢出条件、不触发永久封禁。当前版本属于统计异常检测，不是预训练神经网络，也不宣称能直接识别所有作弊客户端。管理员应结合原有服务端规则证据复核。

AI 默认本地运行且无需 API Key。配置中的 ai_api_enabled、ai_api_key、ai_api_endpoint 是未来外部适配器预留项；当前版本不调用外部 API、不发送玩家行为数据。即使填写 API Key，也不会启用远程分析。


## 误报保护（Endstone 0.6.7）

自动踢出现在至少要求两个不同的高置信度规则同时成立（默认 `auto_kick_min_strong_rules = 2`）。例如，单独的高速移动强证据加上自动搭路弱辅助线索，不再足以自动踢出；必须再有另一项独立强证据。重复触发同一规则不会被当成多个独立强证据。

低置信度/辅助线索仍写入本地审计记录并可供管理员查看，但不会增加持久风险分、降低可信分，也不会重置画像恢复计时。该策略优先避免正常玩家因跑酷、搭桥、网络抖动或单一检测异常而受到自动处罚。


## 移动误报保护（2.1.9 / 0.6.7）

- 行为包侧的速度异常只作为低置信度线索，不单独提升持久风险分或成为自动踢出所需的强证据；Endstone 服务端原生移动检测仍可独立提供高置信度速度证据。
- 玩家死亡重生后，行为包与 Endstone 都会重置移动和搭路采样窗口，并默认给予 5 秒宽限。
- 传送、维度切换和明显位移仍执行原有基线重置；搭路仍为弱辅助证据，不能替代第二项强证据。


## 移动状态识别（2.1.9 / 0.6.7）

- 速度药水按效果等级动态放宽速度阈值；Endstone 使用服务端活动效果等级，不再仅依赖固定的“有/无药水”阈值。
- AI 移动速度特征只采集可比较的地面移动窗口，并按速度药水倍率归一化；鞘翅、飞行、游泳、岩浆、漂浮、缓降和允许飞行状态不混入个人移动基线。
- 悬浮检测排除鞘翅、漂浮、缓降和跳跃提升；状态 API 无法可靠读取时，本次移动/悬浮判定采取跳过策略，不猜测玩家没有效果。
- 跳跃提升不会触发持续异常上升线索。灵魂疾行、激流、击退等特殊移动仍需进一步验证，未可靠识别前不将其描述为已完整支持。
